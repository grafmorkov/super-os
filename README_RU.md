# SUPER OS

Небольшая экспериментальная ОС для x86-64, написанная почти полностью на моем системной языке программирование [Quant](https://github.com/quant-lang/quant). Используется немного GASM для начальной настройки процессора и работы с низкоуровневой фигней.

ПРИМЕЧАНИЕ: **Этот проект я навайбкодил специально для видео. Это эксперимент, а не моя серьезная ОС** 

## Как это работает

QEMU загружает SUPER OS как 32-битный образ Multiboot 1. Небольшой ассемблерный загрузчик настраивает таблицы страниц, переключает процессор в 64-битный long mode и передаёт управление ядру на Quant.

После запуска ядро инициализирует консоль, прерывания, простой аллокатор, систему системных вызовов и оболочку. Также оно умеет загружать ELF64-программы и запускать их в пользовательском режиме (ring 3). Пользовательские программы компилируются с помощью специального таргета Quant `x86_64-superos`.

Большая часть ядра находится в одном файле: `kernel/kmain.qu`. Ассемблер используется там, где без низкоуровневой настройки процессора не обойтись.

```text
QEMU -kernel build/superos.elf [-initrd build/demo.elf]
  -> boot32.s   Multiboot, таблицы страниц, переход в long mode
  -> boot64.s   64-битная точка входа, стек ядра, вызов kmain()
  -> kmain.qu   консоль, драйверы, системные вызовы, ELF-загрузчик, shell
       -> enter_user() -> ELF64-программа в ring 3 через int 0x80
```

## Структура проекта

```text
kernel/
  boot32.s       32-битная точка входа Multiboot и настройка long mode
  boot64.s       64-битная точка входа и стек ядра
  hw.s           GDT/TSS/IDT, PIC/PIT, обработчики прерываний, переходы в ring 3
  kmain.qu       Ядро: консоль, ввод, heap, системные вызовы, загрузчик, shell
  boot32.ld      Скрипт линковки загрузочного ELF32
  kernel64.ld    Скрипт линковки плоского ядра по адресу 0x200000

user/
  hello.qu       Минимальная программа hello world
  demo.qu        Демонстрация системных вызовов

scripts/
  build.ps1 / build.sh           Сборка ядра и пользовательских программ
  run.ps1 / run.sh               Запуск ОС в QEMU
  test-qemu.ps1 / test-qemu.sh   Автоматический тест загрузки без графического окна
  qemu-common.ps1 / qemu-common.sh  Общие функции для запуска QEMU
```

Каждый скрипт представлен в двух вариантах: PowerShell (`.ps1`, для Windows) и bash (`.sh`, для Unix-подобных оболочек). Оба лежат в папке `scripts/` и принимают эквивалентные аргументы. Примеры ниже используют PowerShell, но у каждой команды есть аналог с расширением `.sh`.

## Требования

Для сборки и запуска понадобятся:

- Компилятор Quant, собранный из `..\quant` и поддерживающий таргет `x86_64-superos`. По умолчанию ожидается `..\quant\build\bin\qu.exe`.
- LLVM: `clang.exe` и `ld.lld.exe`. Путь по умолчанию: `C:\tools\clang\bin`.
- QEMU для x86-64: `qemu-system-x86_64.exe`.

Скрипты используют эти пути по умолчанию. При необходимости их можно переопределить переменными окружения:

| Переменная | Назначение |
| --- | --- |
| `QUANT_DIR` | Путь к репозиторию Quant |
| `QUANT_EXE` | Путь к `qu.exe` |
| `CLANG_DIR` | Каталог с `clang.exe` и `ld.lld.exe` |
| `QEMU_EXE` | Путь к `qemu-system-x86_64.exe` |

По умолчанию `QUANT_DIR` указывает на `C:\Users\Zero\repo\quant`.

## Сборка

Собрать ядро и пользовательские программы можно через PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

После сборки появятся следующие файлы:

```text
build/superos.elf   Загрузочный образ ОС
build/hello.elf     Минимальная пользовательская программа
build/demo.elf      Программа для тестирования системных вызовов
```

Чтобы собрать другую пользовательскую программу, передайте её исходник через `-UserPrograms`:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1 -UserPrograms user\demo.qu
```

Имя выходного ELF будет соответствовать имени исходного файла.

Ядро всегда компилируется с `--target x86_64-superos`. При этом само ядро представляет собой обычный код на Quant, скомпонованный в плоский бинарный файл.

Если изменить `..\quant\std\superos\io\io.qu`, необходимо пересобрать компилятор Quant, чтобы обновлённая стандартная библиотека попала в сборку:

```powershell
cmake --build ..\quant\build
```

## Запуск

### Через последовательную консоль

Самый простой способ запустить ОС:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1
```

Для автоматической загрузки и запуска пользовательской программы при старте:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 -Initrd build\demo.elf
```

Последовательная консоль подключена к COM1, поэтому оболочка работает прямо в текущем терминале. Для выхода из QEMU введи `poweroff`. Также можно использовать `Ctrl+C`.

### Через графическое окно QEMU

Чтобы запустить ОС с VGA-консолью в отдельном окне:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 -Gui
```

С загрузкой пользовательской программы:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 -Gui -Initrd build\demo.elf
```

Если GTK недоступен, можно попробовать SDL:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 -Gui -Display sdl
```

Щёлкни по окну QEMU, чтобы вводить команды через эмулируемую PS/2-клавиатуру. Вывод последовательной консоли при этом также отображается в терминале.

- `Ctrl+Alt+G` освобождает клавиатуру и мышь.
- `Ctrl+Alt+F` переключает полноэкранный режим.

Если передан параметр `-Initrd`, ядро автоматически загрузит и запустит указанную ELF-программу один раз при старте, после чего перейдёт в оболочку. Повторно запустить программу можно командой `run`.

## Тестирование

Для проверки загрузки есть отдельный скрипт, который запускает QEMU без графического окна, передаёт команды через последовательный порт, собирает вывод и завершает эмулятор через `isa-debug-exit`.

Запуск стандартного теста:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\test-qemu.ps1
```

Запуск с собственным набором команд:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\test-qemu.ps1 -CommandList "help;ticks;mem;poweroff"
```

Проверка пользовательской программы:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\test-qemu.ps1 -Initrd build\hello.elf
```

Можно также передать программу и список команд:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\test-qemu.ps1 -Initrd build\demo.elf -CommandList "hello from ring 3;poweroff"
```

Доступные параметры:

- `-Initrd` — ELF-файл для загрузки при старте.
- `-CommandList` — список команд, разделённых символом `;`.
- `-BootWaitMs` — время ожидания после загрузки.
- `-CharDelayMs` — задержка между отправкой символов.

Скрипты также учитывают пару особенностей QEMU:

- Если путь к initrd содержит пробелы, файл предварительно копируется в `%TEMP%\superos-initrd\`.
- Последовательная консоль QEMU может терять слишком большие порции входных данных, поэтому тестовый скрипт отправляет символы с небольшой задержкой.

При успешном `poweroff` QEMU может завершиться с кодом `1`. Это ожидаемое поведение: `isa-debug-exit` преобразует код завершения гостевой системы `0` в код `1` на хосте.

## Команды оболочки

Оболочка намеренно сделана простой. Она нужна в первую очередь для тестирования ядра без необходимости пересобирать всё после каждого изменения.

| Команда | Описание |
| --- | --- |
| `help` | Список доступных команд |
| `run`, `exec`, `hello` | Загрузить и запустить ELF, переданный через `-initrd` |
| `echo TEXT` | Вывести текст |
| `clear` | Очистить VGA-консоль |
| `ver` | Показать информацию о версии |
| `mem` | Вывести адреса heap и пользовательского стека |
| `ticks` | Показать количество тиков PIT с момента загрузки |
| `reboot` | Перезагрузить систему через контроллер клавиатуры |
| `poweroff` | Завершить QEMU через `isa-debug-exit`, с запасным вариантом через ACPI |

## Пользовательские программы и системные вызовы

SUPER OS умеет запускать программы на Quant, скомпилированные под специальный таргет ОС:

```powershell
..\quant\build\bin\qu.exe --target x86_64-superos user\hello.qu -o build\hello.elf
```

Компилятор создаёт ELF64 `ET_EXEC` без PIE, с базовым адресом `0x400000` и ABI SysV AMD64.

Ядро загружает сегменты `PT_LOAD`, обнуляет оставшуюся часть `.bss` и передаёт управление программе в ring 3. Верхняя граница пользовательского стека находится по адресу `0x600000`.

Системные вызовы выполняются через `int 0x80`.

| Номер | Название | Аргументы | Результат |
| --- | --- | --- | --- |
| 0 | `read` | `fd, buf, len` | Количество прочитанных байтов |
| 1 | `write` | `fd, buf, len` | Количество записанных байтов |
| 9 | `mmap` | `addr, len, prot, flags, fd, offset` | Адрес |
| 11 | `munmap` | `addr, len` | `0` |
| 12 | `sbrk` | `increment` | Предыдущее значение break |
| 24 | `yield` | Нет | `0` |
| 39 | `getpid` | Нет | `1` |
| 60 | `exit` | `code` | Не возвращается |

Номер системного вызова передаётся через `RAX`, аргументы через `RDI`, `RSI`, `RDX`, `R10`, `R8` и `R9`. Результат возвращается в `RAX`. Ошибки представлены отрицательными значениями `errno`.

Реализация `std::io` для этого таргета находится в `..\quant\std\superos\io\io.qu`. Она предоставляет обёртки над системными вызовами: `print`, `println`, `print_char`, `read`, `write`, `mmap`, `munmap`, `sbrk`, `yield`, `getpid` и `exit`.

Пример минимальной пользовательской программы:

```qu
load "std::io";
using std::io;

@entry i32 main() {
    println("hello from a Quant SUPER OS user program");
    return 0;
}
```

## Карта памяти

Текущая карта памяти выглядит следующим образом:

| Адрес | Назначение |
| --- | --- |
| `0x1000 - 0x3FFF` | Таблицы страниц PML4/PDPT/PD, страницы с identity mapping по 2 МиБ |
| `0x30000 - 0x33FFF` | Временная память ядра: кольцевой буфер ввода, строка оболочки, буфер чисел |
| `0x100000` | 32-битный Multiboot-контейнер |
| `0x200000` | Плоское 64-битное ядро на Quant |
| Начало модуля | Образ `-initrd`, размещаемый QEMU, например по адресу `0x11B000` |
| `0x400000` | Начало пользовательского ELF |
| `0x600000` | Верхняя граница пользовательского стека, который растёт вниз |
| `0x800000 - 0x4000000` | Пользовательская куча для `sbrk` и `mmap` |

Первые 1 ГиБ памяти отображаются с помощью identity mapping и страниц размером 2 МиБ. Эти страницы помечены как доступные пользовательскому режиму, чтобы программы в ring 3 могли обращаться к собственному коду, стеку и куче.

У такого решения есть очевидный недостаток: полноценной изоляции адресных пространств пока нет

## Ограничения

- **Только одна программа за раз.** Нет планировщика, вытеснения процессов и полноценного управления процессами. `yield` пока просто выполняет `hlt`.
- **Простое управление памятью.** `mmap` работает как bump allocator, а `munmap` ничего не делает.
- **Нет файловой системы и блочных устройств.** Пользовательские программы передаются через `-initrd`.
- **Нет поддержки SMP и APIC.** Используется только классическая схема PIC/PIT.
- **Простой последовательный ввод.** Консоль рассчитана на `-serial stdio`, ввод построчный и обрабатывается ядром.
- **Нет полноценной изоляции памяти.** Пользовательский режим существует, но общая identity mapping позволяет программам обращаться к памяти ядра и других программ.

## Зачем всё это

SUPER OS появилась как эксперимент для видео чтобы проверить, можно ли вообще написать ОС на Кванте? Вместо очередной программы в терминале здесь есть загрузчик, ядро, системные взовы и возможность запускать собственные ELF-программы.

Проект не претендует на практическую ценность или полноценность. Мне просто было интересно попробовать написать маленькую ОС на собственном языке с помощью вайб кодинга и посмотреть, что из этого выйдет.

**Не воспринимайте название SUPER OS слишком серьёзно.**
